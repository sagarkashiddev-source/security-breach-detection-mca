Abstract

Protocol & Benchmark Study

The increasing number of cyberattacks has created a significant need for reliable network intrusion detection systems (IDS). Traditional security mechanisms often face challenges in identifying complex and previously unseen malicious activities. Machine Learning (ML) techniques provide an effective approach to analysing network traffic and identifying suspicious patterns. This research presents a controlled comparative evaluation of six traditional ML algorithms—Decision Tree, Random Forest, Support Vector Machine (SVM), K-Nearest Neighbours (KNN), Naive Bayes, and Logistic Regression—using the UNSW-NB15 benchmark dataset (257,673 records representing normal and malicious network activities). Following preprocessing, feature selection, and stratified training/testing procedures, algorithms are evaluated across accuracy, precision, recall, macro-averaged F1-score, ROC-AUC, false positive rate, and computational time to provide an evidence-based assessment of their suitability and limitations for network intrusion detection.

Introduction, Related Work & Research Gaps

I. Introduction & Motivation

Growing dependence on internet services, online banking, cloud computing, and digital communication has sharply increased exposure to cyber threats and security breaches. Traditional signature-based detection and predefined firewall rules struggle to detect complex, novel, or previously unseen attack patterns.

While supervised Machine Learning algorithms offer strong capabilities for analysing network traffic, each algorithm exhibits distinct trade-offs in classification accuracy, minority-attack recall, false positive rates, and computational overhead. Unlike studies relying exclusively on overall accuracy, this study conducts a controlled comparative evaluation under a common benchmark dataset and evaluation protocol—accounting for macro-averaged F1-score, recall, precision, false positive rate, dataset imbalance, feature selection, and computational efficiency.

III. Research Gaps & Problem Statement

G1

Fragmented Algorithm Subsets

Many comparative studies evaluate inconsistent subsets of classifiers across varying datasets and preprocessing pipelines, limiting fair, direct side-by-side comparisons.

G2

Overemphasis on Overall Accuracy

Prior evaluations frequently emphasize overall accuracy without sufficient focus on minority-class recall, macro-averaged F1-score, and False Positive Rates (FPR) under class imbalance.

G3

Decoupled Efficiency Assessment

Classification performance and computational efficiency (training time, prediction latency, CPU/memory footprint) are rarely evaluated jointly under a single experimental protocol.

VI. Classification Error Analysis Model

Evaluates confusion matrices derived from actual model predictions and verified labels. No unverified assumptions about defect propagation between chronological network events are made.

TP (True Positive) Correct

Malicious network activity is accurately detected and flagged as an attack.

TN (True Negative) Correct

Normal, legitimate network traffic is correctly identified and allowed without disruption.

FP (False Positive) Alert Fatigue

Normal activity is misclassified as malicious, generating unnecessary security alerts and analyst fatigue.

FN (False Negative) Critical Risk

Actual malicious activity is misclassified as normal, allowing security breaches to bypass detection undetected.

      VII. Research Questions (RQ1–RQ4) & Hypotheses (H1–H4)

      RQ1

      Which of the six selected machine learning algorithms achieves the best classification performance for network intrusion detection?

      Primary Evidence: Accuracy, precision, recall, F1-score, and ROC-AUC.

      RQ2

      How do the algorithms differ in detecting malicious activities and controlling false positive rates?

      Primary Evidence: Recall, false positive rate, precision, and confusion matrix.

      RQ3

      How do training time and prediction time vary among the selected algorithms?

      Primary Evidence: Training time, prediction time, and resource consumption.

      RQ4

      How does class imbalance influence the detection of minority attack categories?

      Primary Evidence: Class-wise performance, macro-averaged F1-score, and minority-class recall.

      H1 • Classification Performance

      There are statistically significant differences in macro-averaged F1-score among the six selected machine learning algorithms.

      H2 • Threat Detection

      The selected algorithms demonstrate differences in recall and false positive rates when identifying malicious network activities.

      H3 • Computational Efficiency

      The selected machine learning algorithms demonstrate differences in training time and prediction time.

      H4 • Dataset Imbalance

      Class imbalance handling influences the classification performance of machine learning algorithms, particularly for minority attack categories.

      VIII. Experimental Methodology

      Experimental Unit
      Algorithm × Dataset × Experimental Run

      Benchmark & Tasks: UNSW-NB15 serves as the primary benchmark. The primary task is binary classification (Normal vs. Malicious), with multiclass classification considered for individual attack categories subject to label quality.

      Data Assignment & Control: Identical stratified partitions (~80% training / 20% independent testing) ensure fairness. Five-fold stratified cross-validation is applied strictly within the training split for tuning.

      Implementation Stack: Python ecosystem utilizing Scikit-learn, Pandas, and NumPy.

      X & XI. Statistical Analysis Plan & Metric Validation

      Designed to verify whether observed differences in classification performance, threat detection capability, and computational efficiency are statistically significant rather than random variation.

      • 1 Cross-Validation: 5-fold stratified cross-validation across all six algorithms.
      • 2 Descriptive Statistics: Mean, median, standard deviation, and confidence intervals reported per metric.
      • 3 Non-Parametric Testing: Friedman test (where design assumptions hold) followed by appropriate post-hoc pairwise comparisons if significance is detected.
      • 4 Metric Validation (Sec. XI): Standardized formulas ensure balanced representation of detection effectiveness, false alarm control, and runtime efficiency.

      Section XIV

      Discussion

      No single ML algorithm is universally optimal across every cybersecurity environment. Suitability depends on dataset characteristics, attack distributions, available compute, and organizational risk tolerance (e.g., minimizing false alarms vs. maximizing breach recall). The study provides a disciplined framework for context-aware algorithm selection.

      Section XVIII

      Practical Significance

      Organizations, businesses, educational institutions, and government agencies depend on digital infrastructure to manage sensitive information. Side-by-side insights into detection accuracy, false positive rates, and runtime latency help security engineers deploy reliable, resource-appropriate IDS solutions.

      Section XIX

      Future Research

      Future extensions can expand this baseline comparison by integrating advanced ensemble and deep learning models, evaluating cross-dataset generalization (e.g., CICIDS2017, NSL-KDD), incorporating real-time streaming intrusion monitoring, and exploring adaptive concept-drift handling.

      Section XX

      Conclusion

      This research establishes a structured, multi-metric comparative methodology—combining dataset preprocessing, feature selection, stratified evaluation, error analysis, and computational profiling—to systematically benchmark six foundational ML algorithms for network security breach detection.

      XVI. Reproducibility & Artifact Plan

      Preserves complete records of dataset versions, preprocessing scripts, feature selection criteria, random seeds, hyperparameters, and evaluation logs so independent researchers can repeat the comparative benchmark.

      XVII. Ethical Considerations

      Adheres to strict data privacy, confidentiality, and responsible ML principles. Relies exclusively on authorized, publicly licensed cybersecurity benchmark datasets with no identifiable human-participant information.

      Project Explanation & Viva Preparation

      A quick revision section covering the project, dataset, algorithms, metrics, implementation and likely examiner questions.

      Explain the project in 30 seconds

      Our project compares six supervised machine-learning classifiers for identifying normal and malicious network traffic. We use the labelled UNSW-NB15 benchmark, prepare its network-flow features, train Decision Tree, Random Forest, Linear SVM, KNN, Naive Bayes and Logistic Regression, and evaluate their predictions using classification metrics and execution time. The goal is to compare their strengths and limitations for network intrusion detection.

      What the working prototype does

      • Loads separate training and testing CSV files.
      • Maps the binary label to Normal (0) and Attack (1).
      • Preprocesses numerical and categorical features.
      • Trains six supervised classifiers.
      • Calculates metrics from actual predictions.
      • Displays charts, confusion matrices and sample predictions.
      • Exports the measured result table.

      Research integrity reminder

      The charts earlier in this portal are explicitly marked illustrative until replaced with verified experimental output. Use the Live ML Experiment section to generate measured results. The current implementation does not run 5-fold cross-validation, statistical significance testing, live packet capture, attack-family multiclass classification or automatic attack blocking. Do not claim those functions have been implemented.

      Frequently asked viva questions

      1. What is the main objective of your project?

      To compare six machine-learning algorithms for classifying network traffic as normal or malicious, using a common benchmark and consistent evaluation metrics.

      2. What is an Intrusion Detection System?

      An IDS monitors system or network activity to identify suspicious or potentially malicious behaviour.

      3. Why did you choose UNSW-NB15?

      It is a publicly available labelled network intrusion detection benchmark containing normal traffic and multiple attack categories.

      4. How many records are in the documented dataset?

      257,673 total records: 175,341 training records and 82,332 testing records. The application must still report the actual number of rows uploaded and used in each run.

      5. What are the nine attack categories?

      Fuzzers, Analysis, Backdoors, DoS, Exploits, Generic, Reconnaissance, Shellcode and Worms.

      6. What is binary classification in this project?

      The target is represented as two classes: Normal = 0 and Attack = 1. The current model does not identify the individual attack family.

      7. What is supervised learning?

      It is machine learning using labelled examples, where the correct output is provided during training.

      8. Explain Decision Tree.

      It predicts a class by following feature-based conditions arranged in a tree of decisions.

      9. Explain Random Forest.

      It combines predictions from multiple decision trees, commonly using majority voting for classification.

      10. Explain SVM.

      Support Vector Machine finds a decision boundary, called a hyperplane, that separates classes. This implementation uses LinearSVC.

      11. Explain KNN.

      K-Nearest Neighbours predicts a record's class from the majority class among its K closest training examples.

      12. Explain Naive Bayes.

      It is a probabilistic classifier based on Bayes' theorem and a conditional-independence assumption. This implementation uses MultinomialNB.

      13. Explain Logistic Regression.

      It estimates the probability of a class and applies a decision threshold to make a binary prediction.

      14. What is accuracy?

      The proportion of all predictions that are correct: (TP + TN) / (TP + TN + FP + FN).

      15. What is precision?

      Of the records predicted as attacks, the proportion that are actually attacks: TP / (TP + FP).

      16. What is recall?

      Of all actual attacks, the proportion correctly detected: TP / (TP + FN).

      17. What is F1-score?

      The harmonic mean of precision and recall: 2 × (precision × recall) / (precision + recall).

      18. What is a false positive?

      Normal traffic incorrectly classified as an attack, potentially generating a false alarm.

      19. What is a false negative?

      Actual attack traffic incorrectly classified as normal. This can allow malicious activity to go undetected.

      20. What is ROC-AUC?

      It measures how well a classifier separates the two classes across different decision thresholds.

      21. Why separate training and testing data?

      Training data is used to fit the model; separate testing data estimates how well it performs on unseen records.

      22. What is overfitting?

      When a model learns training-specific details or noise and does not generalise well to unseen data.

      23. What is data leakage?

      When information that should not be available during training influences the model, making evaluation results overly optimistic.

      24. Which tools and technologies are used?

      Python, Pandas, NumPy, Scikit-learn, Streamlit and Plotly.

      25. What is the research gap?

      The study aims to provide a controlled comparison of six classifiers using consistent data partitions and multiple detection and efficiency metrics, rather than relying on accuracy alone.

      26. What are H0 and H1?

      H0 states there is no statistically significant performance difference; H1 states there is a statistically significant difference. A statistical test and p-value are required before deciding between them.

      27. Which algorithm performed best?

      Use the actual result table generated by the Live ML Experiment. Do not name a winner before the experiment is run and its metrics are checked.

      28. Does the application detect live attacks?

      No. It classifies prepared, labelled network-flow records from CSV files. It does not capture live packets or block attacks.

      29. Can it identify the exact attack family?

      Not in the current binary classification configuration. Multiclass attack-family classification is future work.

      30. What is the future scope?

      Future work may include multiclass classification, additional benchmark datasets, real-time packet ingestion, statistical significance testing, deep learning and carefully evaluated deployment integrations.
